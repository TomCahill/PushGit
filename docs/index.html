Built to prove a git GUI can be both rich and light

Most feature-rich git clients today are built on Electron. That choice shows up as idle memory that climbs over a working day, multi-second startup, and installers in the hundreds of megabytes. PushGit makes the opposite architectural bets from the start — a native webview instead of bundled Chromium, an in-process git library instead of shelling out per action — rather than retrofitting performance later.

None of that bloat is a one-off bug in other tools — it's the accumulated cost of years of feature accretion on top of a heavyweight runtime: dashboards, AI text generation wired into every input, mandatory accounts, and telemetry with no opt-out, all loaded before you've clicked a single commit.

PushGit's scope is narrow on purpose: render history clearly, and make staging, branching, merging, diffing, stashing, and syncing fast. Every one of those is bounded, well-understood, local-first work — there's no technical reason it should cost hundreds of megabytes of idle RAM.

Everything you actually do with git, done well

No project boards, no PR review, no AI text generation bolted onto every field. Just the operations that make up a real git workflow.

☉

Visual commit graph

Stable lane layout, persistent branch/tag colors, a live "uncommitted changes" row, and instant search/filter by message, SHA, author, or ref — smooth even on large histories.

✎

Staging & commits

Stage whole files, individual hunks, or individual lines. Amend with one toggle, prefill from your commit template, and optionally skip hooks per commit.

⇆

Diffing

Inline or side-by-side views, syntax-highlighted per file type, with rename/copy/typechange detection so a moved file reads as one change, not a delete-and-add.

↪

Branching & rebase

Create, checkout, rename, delete (local and remote), merge, and both non-interactive and drag-to-reorder interactive rebase, with a real three-way conflict editor.

💾

Stash

Create, apply, pop, drop, rename, and selectively stash just the files you choose — not the whole working directory.

⇄

Remotes

Fetch, pull, and push over SSH or HTTPS using your existing credentials, with ahead/behind tracking and unpulled remote commits shown greyed-out right on the graph.

⎋

Undo, always

A real undo/redo stack — not a single safety net — backed by full repository snapshots, covering commits, branch changes, merges, rebases, and stash actions.

⌕

Command palette

Fuzzy search commands, branches, files, and commits from the keyboard without ever touching the mouse.

⚖

Cherry-pick & blame

Single- or multi-commit cherry-pick with conflict handling, plus per-line blame and file history for tracing where a change came from.

⋔

GitFlow support

Start and finish features, releases, and hotfixes against the same git-flow config the AVH CLI uses — interoperable with repos set up either way.

✦

AI commit messages — opt-in

Off by default. When enabled, generate commit messages from your staged diff via your own API key, or entirely on-device with a bundled local model — your choice, never assumed.

⚙

Repo maintenance

A repo-health indicator based on loose/packed object counts, with a one-click git gc when it's actually worth running.

A pure, local git client

PushGit talks to whatever remote you've configured over plain SSH or HTTPS, and nothing else. No hosting integrations, no project-management surfaces, no accounts to create.

No telemetry No crash reporting No mandatory account Works fully offline No GitHub/GitLab/Jira integrations

Built on a lighter stack

Tauri pairs a Rust core with the OS's native webview instead of bundling Chromium. Git access goes through git2-rs (libgit2) for the vast majority of operations, so most actions never fork a git subprocess at all — with the real git binary as an escape hatch only where libgit2 genuinely can't do the job (interactive rebase, some credential-helper flows).

Tauri — app shell Rust — backend core git2-rs — libgit2 bindings Svelte — frontend UI WebKitGTK — native Linux webview
